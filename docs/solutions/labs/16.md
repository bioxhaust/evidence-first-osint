# Разбор лабораторной 16

[Вернуться к заданию](../../practice/labs/16.md).

Для штатного `payments-dirty.csv` подтверждённая сумма C-17 должна совпасть с ручным расчётом: **5 000 000 TST**. В JSON вывода анализатора ожидается поле `total_settled_c17` с этим значением. Смысл результата ограничен исполненными уникальными строками нужного контракта; наличие карантина и исключений надо читать вместе с суммой.

`read_api.py` работает с локальным файлом. Даже если его структура напоминает ответ сервиса, выполнение команды не проверяет доступность сервиса, действительность ключа или полноту удалённой выгрузки. Правильная запись: «локальный JSON успешно прочитан; сеть не использовалась».

Пример объяснения фильтра: «PAY-03 не входит в итог, поскольку имеет статус `scheduled`; его числовая сумма сама по себе не делает его исполненным платежом». Другой хороший пример — сравнение контрактного ID вместо текстового названия поставщика.

У результата намеренно испорченной копии нет универсального текста ошибки: он зависит от выбранного повреждения и версии инструмента. Сдайте фактический вывод, код завершения при доступности и объяснение. Если скрипт поместил строку в карантин, это отличается от полной остановки. Если завершился без обнаружения неожиданного типа проблемы, отметьте ограничение валидатора и предложите проверку, не скрывая результат.

Полные баллы не требуют изменения исходного кода. Важнее уметь повторить расчёт, увидеть ошибку входа и не считать технический успех подтверждением содержания. Для читателя без Python лабораторная 15 обеспечивает тот же обязательный учебный результат по данным.
