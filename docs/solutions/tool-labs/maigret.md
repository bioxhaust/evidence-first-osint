# Разбор: Maigret, два экспорта и исправленное правило

Это решение к [практической лабораторной Maigret](../../practice/tool-labs/maigret.md). Сначала сохраните собственные файлы и вывод. Все объекты синтетические.

## Что действительно получилось в исходном запуске

**Maigret 0.6.6, Python 3.12.11, macOS arm64.** Четыре учебные записи дали четыре разных ситуации:

- **SYNTHETIC Present:** CSV `Claimed`, HTTP 200. Страница содержит `SYNTHETIC PROFILE: route_lab. LEARNER-A training notes. No real person.` Проверяемый профиль в нашем корпусе существует. Реальная личность или управление аккаунтом этим не устанавливаются.
- **SYNTHETIC Soft404:** CSV `Claimed`, HTTP 200. Но текст страницы: `SYNTHETIC GENERIC PAGE: no profile exists here; the server returns HTTP 200 for everyone.` Это ложный плюс правила `status_code`.
- **SYNTHETIC Missing:** CSV `Available`, HTTP 200. Текст содержит `SYNTHETIC PROFILE NOT FOUND`, который совпал с `absenceStrs`. Здесь подтверждён отрицательный исход именно известного учебного правила.
- **SYNTHETIC Slow:** CSV `Unknown`, HTTP 0, `Request timeout error`. Ноль означает отсутствие полученного HTTP-ответа в этом экспорте; это не реальный HTTP-код сервера. Ответ задержан на секунду, лимит Maigret — 0,25 секунды.

В исходном JSON находятся **Present и Soft404**, две записи `Claimed`. Missing и Slow отсутствуют: генератор `simple` пропускает всё, кроме положительных результатов. Поэтому корректный ответ заказчику — передать CSV и журнал проверки вместе с JSON, объяснив границы формата. Файл из двух положительных строк нельзя называть полным протоколом четырёх проверок.

Позднее ручное открытие Slow может получить текст, который первоначальный запуск не успел прочитать. Сохраните это как новое наблюдение с собственной датой и способом получения. Исходную строку `Unknown` не удаляйте.

## Правка, которая изменила результат

В рабочей копии изменена только запись `SYNTHETIC Soft404`:

```json
"checkType": "message",
"absenceStrs": ["no profile exists here"]
```

Это фрагмент записи, а не полная база. Маркер взят из фактически полученной страницы. Не следует заменять его общим словом `profile`: оно встречается и на существующем профиле.

В повторном запуске Soft404 стал `Available`. Present остался `Claimed`; Missing — `Available`; Slow — `Unknown`. JSON теперь содержит только Present, CSV по-прежнему сохраняет четыре строки. Ни одна страница не была удалена и ни один профиль не «исчез»: изменилось правило интерпретации неизменного ответа сервера.

Правка доказала работоспособность одного маркера на текущем локальном тексте. Она не гарантирует точность на другом языке, новой версии страницы, редиректе или реальном сервисе. Для нового правила нужны отдельные известные положительные и отрицательные примеры.

## Пример короткого вывода

> В четырёх проверках Maigret сообщил о двух аккаунтах. Ручное чтение подтвердило существование одного учебного профиля; второй плюс вызван общей страницей HTTP 200. JSON содержит только плюсы и скрывает отрицательный исход и тайм-аут, поэтому полный протокол включает CSV. После изменения Soft404 на проверку точного маркера отсутствия число плюсов сократилось до одного; остальные исходы сохранились. Тайм-аут не позволяет судить о содержании страницы в момент исходного запроса. Эти результаты описывают страницы стенда и не устанавливают личность их оператора.

## Почему Sherlock и Maigret могут одинаково ошибаться

Оба инструмента могут использовать один и тот же ненадёжный признак: ответ 2xx. Два совпавших результата не являются двумя независимыми подтверждениями. Важен переход к исходному содержимому и проверка правила, а не голосование программ.
