# SpiderFoot: собрать цепочку событий и проверить ложную связь

**Практика, 45–60 минут после установки.** Две учебные страницы содержат одинаковую строку, похожую на код аналитики. Автоматизация найдёт совпадение. Ваша задача — выяснить, что именно обнаружено, откуда пришёл результат и достаточно ли его для вывода об общем владельце.

После задания у вас будут три собственных запуска, CSV/JSON событий, связи между исходными и производными событиями и короткий вывод с доказательством. Для первого результата не нужен платный сервис или API-ключ.

## Что здесь действительно запускается

Исполняется код **настоящих модулей SpiderFoot**: `sfp_spider`, `sfp_webserver`, `sfp_webanalytics`. Модуль crawler получает страницы с вашего локального сервера; остальные модули обрабатывают его события. Учебный launcher передаёт события между модулями и сохраняет их поля.

Это **модульный практикум**, а не запуск полного стандартного сканера `sf.py`, веб-интерфейса или всех интеграций SpiderFoot. JSON/CSV и таблица рёбер здесь экспортируются кодом курса из настоящих событий модулей; они не выдаются за штатный экспорт полного сканера.

Проверен commit `0f815a203afebf05c98b605dba5cf0475a0ee5fd`, внутри которого версия обозначена **4.0.0**; среда — Python **3.12.11**, macOS arm64. Последний packaged release GitHub на дату проверки — v4.0 от 7 апреля 2022 года. Это не основание обещать актуальность каждой интеграции. Состояние исходников и запуск зафиксированы **3 ноября 2026 года**.

## 1. Подготовьте инструменты

Скачайте репозиторий курса и откройте терминал в его корневой папке. Нужны Python 3.12 и Git. Команды используют пути macOS/Linux; Windows отдельно не проверялся. Начинайте с новой папки `scratch/spiderfoot-upstream`:

```sh
python3 --version
python3 -m venv scratch/spiderfoot-venv
git clone https://github.com/smicallef/spiderfoot.git scratch/spiderfoot-upstream
git -C scratch/spiderfoot-upstream checkout 0f815a203afebf05c98b605dba5cf0475a0ee5fd
scratch/spiderfoot-venv/bin/python -m pip install -r docs/assets/spiderfoot/requirements-tested.txt
scratch/spiderfoot-venv/bin/python scratch/spiderfoot-upstream/sf.py -V
```

Если `python3` указывает на другую версию, используйте команду своего установленного Python 3.12 при создании среды. Первая установка скачивает зависимости и может занимать несколько минут. Файл requirements фиксирует **фактически установленный набор**, а не предложение заменить им зависимости любого будущего SpiderFoot. Команда `-V` подтверждает только запуск вывода версии.

Исходники остаются отдельной копией upstream. Launcher проверяет хеши задействованных файлов по [списку](../../assets/spiderfoot/upstream-lock.json); их не нужно редактировать для прохождения задания.

## 2. Запустите собственные страницы и модули

В первом терминале:

```sh
python3 tools/spiderfoot_fixture_server.py
```

Откройте напечатанный адрес `http://127.0.0.1:54371/index.html`. Это ваш компьютер. Все четыре страницы помечены SYNTHETIC и вымышлены. Не меняйте сервер, порт и объект поиска на посторонний сайт.

Во втором терминале из корня курса:

```sh
scratch/spiderfoot-venv/bin/python tools/run_spiderfoot_local.py
```

В `scratch/spiderfoot-run-01/` появятся:

- `events.json` и `events.csv` — события, их модули, данные, ID родителя и URL происхождения;
- `edges.csv` — связи родительского и дочернего событий;
- `run.json` — версия, выбранные модули, число полученных страниц и границы запуска.

Если каталог уже существует, укажите новый: `--output scratch/spiderfoot-repeat-01`. Прошлая попытка не перезаписывается.

Найдите событие типа `WEB_ANALYTICS_ID`. Запишите его значение, модуль, `parent_id` и `source_url`. Затем найдите родителя по `id`. **Какие данные породили эту находку?** Поднимитесь по родителям до исходной страницы. Это первое конкретное умение: читать происхождение результата автоматического инструмента.

## 3. Проверьте совпадение руками

Найдите второе событие `WEB_ANALYTICS_ID`. Откройте соответствующие страницы и их HTML-исходник: в браузере можно выбрать «Просмотреть код страницы» или открыть файлы `docs/assets/spiderfoot/pages/alpha.html` и `beta.html` в редакторе.

Скопируйте точный контекст найденной строки. Ответьте:

1. Строка находится в исполняемом скрипте, ссылке или комментарии?
2. Доказывает ли извлечение строки, что браузер передаёт данные в систему аналитики?
3. Как источник описывает происхождение шаблона? Назовите альтернативу версии «один владелец».
4. В событии стоит `upstream_confidence=100`. Кто присвоил это значение и что оно измеряет в этом запуске?

Проверьте также `WEBSERVER_BANNER`. Относится ли одинаковый баннер к личности автора проекта или к одному учебному HTTP-серверу? Сохраните цитату из источника и своё ограниченное заключение.

??? tip "Подсказка: результат программы и вывод исследователя"
    Парсер ищет строку определённого вида. Он может найти её в комментарии или образце кода. `confidence` созданного события по умолчанию равно 100; в этом упражнении оно не вычисляется из независимых подтверждений владельца.

## 4. Измените один параметр и объясните разницу

Отключите только извлечение аналитики:

```sh
scratch/spiderfoot-venv/bin/python tools/run_spiderfoot_local.py --without-analytics --output scratch/spiderfoot-run-02
```

Сравните количество полученных страниц и события `WEB_ANALYTICS_ID`. Если событий больше нет, означает ли это, что строки исчезли из страниц? Прочитайте исходный HTML ещё раз. Результат зависит от выбранных модулей, а не только от содержания сайта.

Теперь выполните ограниченный обход одной страницы:

```sh
scratch/spiderfoot-venv/bin/python tools/run_spiderfoot_local.py --max-pages 1 --output scratch/spiderfoot-run-03
```

Найдены ли ссылки на страницы, которые не были загружены? Сравните `LINKED_URL_INTERNAL` и `TARGET_WEB_CONTENT`. **Обнаруженная ссылка и прочитанная страница — разные стадии.** Не трактуйте отсутствие извлечённого идентификатора как отсутствие его на непрочитанных страницах.

После завершения остановите свой сервер `Ctrl+C`.

## Что сдать

Три каталога запуска и записку на 150–250 слов:

- одна цепочка «исходный URL → содержимое → извлечённый идентификатор» с ID событий;
- точная цитата, объясняющая совпадение двух страниц;
- сравнение трёх запусков: модули, охват, результаты и причина различий;
- что установлено, что осталось неизвестным и какая проверка могла бы различить ваши версии.

**10 баллов:** 2 — собственные запуски и версии; 2 — происхождение события восстановлено; 2 — найден контекст совпавшей строки; 2 — выбор модулей отделён от изменения источника; 2 — ограниченный охват и поле confidence не превращены в доказательство личности. Чтение чужого лога не заменяет ваш запуск.

`edges.csv` можно дополнительно импортировать в Gephi как таблицу направленных рёбер, но рисунок лишь визуализирует происхождение событий. Импорт Gephi в этой лабораторной не проверялся и не обязателен.

## Ограничения и ошибки запуска

SpiderFoot объединяет **активные** и **пассивные** методы. `sfp_spider` активно обращается к указанному HTTP-серверу. `sfp_webserver` и `sfp_webanalytics` анализируют уже полученные события в этом запуске. Нельзя считать любой набор модулей пассивным только из-за названия инструмента. Часть внешних интеграций требует API-ключей или оплаты; они здесь не включены.

Launcher допускает только фиксированный localhost, три выбранных модуля и пределы обхода; прокси из окружения не наследуются. Guard ограничивает стандартные Python-соединения и DNS на проверенном пути. Это **не системная песочница**, не проверка произвольного стороннего кода и не встроенная гарантия SpiderFoot. Сетевая установка зависимостей происходит отдельно от ограниченного запуска.

- Нет `SpiderFoot`/модуля: проверьте путь upstream и Python из созданной среды.
- Хеш исходников не совпал: проверьте указанный commit и отсутствие собственных изменений upstream; не отключайте проверку ради продолжения.
- Не получено содержимое: проверьте, что ваш сервер работает и страница открывается. Ошибка соединения не означает отсутствие сайта.
- Порт занят: используйте именно свой уже запущенный стенд или остановите его. Не завершайте неизвестный процесс.
- Установка на другой системе не прошла: сохраните версию Python и сообщение. Указанная проверка не подтверждает совместимость всех ОС.
