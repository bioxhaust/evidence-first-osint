# GitHub-инструменты: настоящий запуск и проверка результата

**Время: 60 минут вместе с лабораторной; первая установка Python может потребовать дополнительного времени.** Запустим Sherlock на четырёх учебных HTTP-страницах. Он найдёт два «профиля», хотя один результат заведомо ложный. Вы сможете увидеть ошибку, объяснить её и сохранить воспроизводимый запуск.

## Результат

Вы установите реальный открытый инструмент в отдельную среду, проверите его команды и испытаете правило обнаружения на известном примере. Затем сопоставите кандидатов со сведениями об их происхождении. Урок входит в основу курса: владение инструментом включает проверку его ошибок и области применимости.

## До начала

Пройдите [публичные профили](19-public-profiles.md), скачайте репозиторий и откройте терминал в папке с `tools` и `docs`. Программировать не требуется: команды можно повторить буквально. Проверенная среда — macOS arm64, Python 3.14.6, Sherlock 0.16.2. Для установки нужен интернет; подписка, аккаунт и API-ключ не нужны. Работа других систем в этом упражнении отдельно не заявляется.

Локальный стенд обслуживает только `127.0.0.1:54369`. Адрес обозначает ваш компьютер. Не заменяйте учебный username на имя постороннего человека; настоящие платформы не являются целями этой лабораторной.

## Метод

**GitHub-репозиторий** содержит исходники, историю изменений и документацию. Сам факт размещения на GitHub не гарантирует безопасность или точность. Перед установкой проверьте автора проекта, README, лицензию, зависимые пакеты, релиз и параметры. **Виртуальная среда** отделяет Python-пакеты от других проектов, но не является изоляцией сетевых прав или файлов.

Три изученных проекта решают разные задачи. [Sherlock](https://github.com/sherlock-project/sherlock) ищет кандидатов по username; в проверенной версии используются HTTP-статусы и текстовые маркеры. [Maigret](https://github.com/soxoj/maigret) также исследует username и извлекает дополнительные сведения, поэтому его исходные настройки требуют особенно внимательного ограничения задачи. Оба проекта имеют MIT-лицензию. [ExifTool](https://github.com/exiftool/exiftool) читает и изменяет метаданные файлов; он полезен для проверки собственного изображения до публикации и не является поисковиком аккаунтов. Его README указывает условия Perl Artistic License или GPL.

На 2026-11-03 актуальные опубликованные GitHub-релизы Sherlock и Maigret — 0.16.2 от 8 сентября и 0.6.6 от 18 сентября. У ExifTool просмотрена история 13.60 от 28 октября; сам проект помечает последним production-релизом 13.55. Даты — наблюдение о сопровождении, а не обещание работоспособности каждой платформы. Подробная проверка источников сохранена в [исследовании инструментов](https://github.com/bioxhaust/evidence-first-osint/blob/main/research/profile-tools-review.md).

**HTTP 200** означает успешную передачу ответа, а не наличие искомого профиля. Общая страница входа или мягкая ошибка тоже может возвращать 200. Проверяемый маркер отсутствия полезнее только пока он соответствует поведению сайта. **Тайм-аут** описывает незавершённый запрос; он не устанавливает отсутствие аккаунта.

Для этого урока custom JSON задаёт четыре локальных маршрута. Учебный launcher вызывает установленный Sherlock CLI с поддерживаемыми `--json`, `--timeout`, `--print-all`. Он дополнительно ограничивает Requests локальным адресом. Это отдельный код курса, а не встроенная гарантия Sherlock: просмотр исходника обнаружил автоматический запрос обновления даже при локальной базе. Guard блокирует его до выхода в сеть; `--ignore-exclusions` применён только к нашим четырём вымышленным правилам, а не как совет для реального поиска.

## Разобранный пример

1. Создайте отдельную среду и проверьте установленный CLI. `python3.14` — имя проверенного интерпретатора; версию своей среды запишите в журнале.

```sh
python3.14 -m venv scratch/sherlock-venv
scratch/sherlock-venv/bin/python -m pip install sherlock-project==0.16.2
scratch/sherlock-venv/bin/sherlock --help
```

2. В первом терминале из корня курса запустите собственный учебный сервер:

```sh
python3 tools/profile_fixture_server.py
```

3. Во втором терминале из той же папки запустите настоящий Sherlock через ограничивающий launcher:

```sh
scratch/sherlock-venv/bin/python tools/run_sherlock_local.py
```

4. Сравните результат с известными ответами сервера. `Present` получает плюс и действительно содержит учебный профиль. `Soft404` тоже получает плюс, но текст сообщает об общей странице без профиля. `Missing` содержит маркер `PROFILE NOT FOUND` и получает `Not Found`. `Slow` отвечает позже тайм-аута и получает `Timeout Error`. Число «2 results» не означает двух доказанных аккаунтов.
5. Проверьте строку guard: ожидаются четыре локальных запроса и одна заблокированная внешняя попытка обновления. Откройте [фактическую выдержку запуска](../assets/profiles/sherlock-run.json) только для сверки. Если у вас другой результат, сохраните его и разберите причину; не подгоняйте отчёт.
6. Остановите сервер `Ctrl+C`. Затем повторите уже знакомое сопоставление пяти карточек отдельным офлайн-помощником:

```sh
python3 tools/profile_candidates.py docs/assets/profiles/scanner-results.json docs/assets/profiles/profiles.json
```

Этот помощник обрабатывает вымышленный TrainingScanner JSON, **не** экспорт Sherlock. Ожидаются пять уникальных кандидатов, две подтверждённые в корпусе связи, один кандидат и две неизвестности. Все шесть исходных наблюдений остаются в `ledger`.

## Самостоятельная работа

Выполните [лабораторную инструментов](../practice/labs/20.md): сохраните собственный запуск, проверьте Soft404 чтением ответа, объясните тайм-аут и составьте карточку выбора ещё одного GitHub-проекта. Если установка недоступна, можно разобрать сохранённый лог, но техническую часть отметьте как невыполненную. Чтение чужого лога не является использованием CLI.

## Критерии успеха

Указаны версия, команды и фактический результат. Правильный плюс отличён от ложного; ошибка не объявлена отсутствием. Вы объясняете работу custom JSON и guard, сохраняете исходные данные и не объединяете аккаунты по username. Выбранный инструмент отвечает конкретному вопросу, а его лицензия не перепутана с правами на чужие данные.

## Ошибки и ограничения

Не запускайте найденный скрипт вслепую с повышенными правами. Не считайте `--local` запретом сети: в Sherlock это выбор встроенной базы, которая содержит настоящие сайты. Не применяйте массовый поиск, рекурсию или обход ограничений ради прохождения упражнения. Виртуальная среда и наш guard не заменяют проверку новой версии кода. Реальный поиск по собственным аккаунтам требует отдельной оценки правил сервисов и объёма запросов.

## Самопроверка

1. **Два плюса означают два профиля?** Нет: Soft404 показывает, как эвристика HTTP-статуса ошибается на общей странице.
2. **Что доказывает успешный `--help`?** Работоспособность установленной команды справки, но не точность поиска или доступность платформ.
3. **Почему Python-среда не гарантирует отсутствие сетевых запросов?** Она отделяет зависимости; обычный код сохраняет сетевые возможности процесса.
4. **Можно ли называть офлайн-помощник запуском Sherlock?** Нет. Это разные программы, входы и проверенные результаты; журнал должен различать их.
