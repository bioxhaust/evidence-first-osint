# Независимая техническая проверка

Дата: **3 ноября 2026 года**. Проверка выполнена отдельным агентом от подготовки уроков и упаковки проекта. Среда локального запуска: macOS 26.0.1, ARM64, Python 3.12.11. Это проверка данной среды, а не обещание совместимости со всеми операционными системами.

## Подтверждено запуском

- `python -m unittest discover -s tests -v`: **11 тестов, все прошли**. Проверяются фильтры суммы, граница даты, сохранность исходного файла, журнал каждого исключения, неоднозначные денежные форматы, конфликтующие идентификаторы, неполные строки, схема локального JSON, целостность материалов и обнаружение потерянных HTML-файлов/якорей.
- `python tools/analyze_case.py docs/assets/case/payments-dirty.csv`: **5 000 000 TST**, две включённые записи. Шесть исходных строк получили решения `included`, `duplicate`, `included`, `not_settled`, `quarantine`, `other_contract`; неизвестная сумма сохранена в сырой строке карантина.
- `python tools/read_api.py docs/assets/case/api-response.json`: **4 записи**, PAY-01–PAY-04. Команда не обращается к сети и не определяет, какие платежи исполнены.
- `python tools/check_fixtures.py`: **25 файлов** соответствуют SHA-256 и размеру в манифесте, неучтённых файлов корпуса нет. Индекс README и сам манифест исключены из хеширования по описанному правилу.
- Pillow извлёк свойства двух настоящих файлов JPEG. У оригинала `DateTimeOriginal = 2025:05:03 09:00:00`; у обрезанной копии этого поля нет. У обоих отсутствуют GPS и `OffsetTimeOriginal`. Значения и размеры совпали с опубликованным `metadata.json`.
- `ffprobe` проверил MP4: H.264, 1200 × 760, 12 кадров/с, 72 кадра, **6,000 секунд**. Видимая подпись SYNTHETIC и схема ориентиров дополнительно просмотрены в `repost.jpg`.
- Оба блока Python в уроке 16 выполнены. Локальный расчёт вернул PAY-01, PAY-02 и 5 млн TST; необязательный пример одного HTTP-запроса вернул `python/cpython` и URL репозитория. Это подтверждает один успешный запрос в указанную дату, а не постоянную доступность API.
- Все четыре пары исходного времени и UTC в `timeline.csv` эквивалентны. Время публикации P01 помечено `publication`.
- Генератор выполнен в отдельном временном каталоге: создал 25 файлов с действительным манифестом. Семантика метаданных совпала с поставляемым корпусом; пять JPEG совпали побайтно в этой среде. Шрифты и кодеки в других средах могут изменить байты, поэтому всеобщее совпадение хешей при пересоздании не заявляется.
- `python -m compileall -q tools tests` завершился успешно.

Детали запусков: [qa-runtime.json](evidence/qa-runtime.json). Итог сборки и проверки навигации, выполненные после интеграции всех страниц, фиксируются на [странице качества](../docs/about/quality.md).

## Исправления по результатам проверки

1. Неполная строка CSV ранее могла вызывать исключение типа вместо понятного решения. Теперь строки с недостающими или лишними ячейками попадают в карантин с исходными значениями. Отсутствие обязательного столбца продолжает останавливать обработку всего файла.
2. Чтение локального API теперь явно отклоняет неверный корневой тип JSON, неправильную версию схемы, пустые/нестроковые и повторяющиеся идентификаторы. Ошибка печатается кратко, программа возвращает код 2. Это минимальная схема упражнения, не валидатор произвольного сервиса.
3. Уточнены `timeline.csv` и генератор: T03 описывает время публикации, хотя текст публикации содержит утверждение о событии.
4. В `metadata.json` явно добавлены `OffsetTimeOriginal` и `timezone_present` по реальному чтению EXIF. Обновлены только соответствующие записи манифеста; изображения не перезаписывались.

## Воспроизводимая интеграционная проверка

Из корня репозитория после установки `requirements-dev.txt`:

```sh
python -m unittest discover -s tests -v
python -m mkdocs build --strict
python tools/check_project.py
```

`check_project.py` проверяет 18 номеров уроков и девять обязательных разделов каждого, наличие 18 лабораторных и решений, трёх проектов и решений, итогового кейса, двуязычных ключевых ресурсов, локальные цели Markdown-ссылок, файлы и якоря ссылок в собранном HTML, наличие `alt` у изображений, известные маркеры незавершённого текста и манифест. Он также ищет несколько распространённых форматов секретов без вывода их значений. Поиск секретов не является всеобъемлющим сканером персональных данных, а наличие `alt` не заменяет оценку его смысла или проверку доступности браузером.

Проверка не делает сетевых запросов к внешним ссылкам и не объявляет методически правильным любой урок, у которого есть нужные заголовки. Содержательная редактура, права на материалы и проверка интерфейса рассматриваются отдельно.

## Полная проверка внешних ссылок курса

Повторный отдельный аудит охватил **55 уникальных HTTP(S)-адресов**, полученных из ссылок и изображений отрендеренного Markdown всех `docs/**/*.md`. Фрагменты якорей объединены по одному адресу. Ссылки на сам публикуемый проект исключены, поскольку их доступность проверяется после публикации. Текст URL внутри примеров кода не превращался в запрос; необязательный GitHub API-пример проверен отдельно выше. Зарезервированные учебные домены `.example` не запрашиваются.

Первый проход: **52 ответа HTTP 200**, два ответа **HTTP 202 без тела** от EUR-Lex и один **HTTP 502** от поиска `crt.sh/?q=example.com`. Однократная перепроверка crt.sh вернула **HTTP 200** с заголовком `crt.sh | example.com`, поэтому оснований считать endpoint постоянно сломанным нет. Два альтернативных официальных адреса EUR-Lex также вернули 202 без тела. Это ограничение получения содержания в данной среде; наличие адреса и код 2xx не подтверждают, что текст GDPR был прочитан в этом проходе. Канонические правовые ссылки не заменены непроверенной копией. В этом проходе ответов 403, 404 или 429 не было.

Результаты, включая первые ошибки, сохранены в [qa-all-external-links.json](evidence/qa-all-external-links.json): статус, итоговый URL, заголовок, объём ответа и страницы курса со ссылкой. Тела ответов не сохраняются. HTTP 200 не гарантирует релевантное содержание, работоспособность функций сервиса, бесплатность или разрешение на сбор данных. Заголовки успешных ответов просмотрены; явных страниц «не найдено» среди них не обнаружено. Приложения вроде Copernicus Browser требуют выполнения JavaScript, поэтому их краткая HTML-оболочка не является проверкой работы карт.

Для повторения при установленном окружении MkDocs:

```sh
python tools/check_external_links.py --date 2026-11-03
```

При новом запуске передайте фактическую дату проверки. Скрипт использует шесть потоков, timeout 15 секунд и ограничение читаемого ответа 4 МиБ. Прерванный по размеру ответ явно отмечается. Внешняя проверка отделена от CI, чтобы временная ошибка чужого сервера не подменяла проверку собственного курса.

## Повторный просмотр самого проверяющего скрипта

Найден и исправлен пропуск ссылок вида `//bioxhaust.github.io/evidence-first-osint/...`: теперь адреса без явно указанной схемы на том же хосте проходят локальную проверку целей и якорей. Ссылка на корень проекта без завершающего слеша также распознаётся. Два теста подтверждают принятие существующего якоря и обнаружение отсутствующего якоря/файла, включая такой адрес без схемы.

Оставшиеся границы проверки обозначены явно:

- CSS `url()`, `srcset`, адреса, создаваемые JavaScript, и поведение поиска не проверяются статическим HTML-парсером; их следует проверять браузером.
- У внешних URL не проверяются якоря, авторизация, географическая доступность или рабочие функции.
- Для README и других файлов вне сайта проверяются локальные пути, но не специфические якоря GitHub Markdown. Для документов курса окончательным источником якорей служит собранный HTML.
- Регулярное выражение исходных Markdown-ссылок не является полным Markdown-парсером; для страниц сайта его дополняет проверка всех `href`, `src` и `poster` в HTML. Сложный новый синтаксис вне сайта требует отдельного просмотра.
- Девять заголовков, минимальная длина и отсутствие нескольких известных маркеров незавершённого текста не доказывают содержательной полноты; это задача редакторской проверки.
- Наличие атрибута `alt` не доказывает его осмысленность, соответствие контраста или клавиатурную доступность. Поиск известных форматов токенов не доказывает отсутствие всех видов секретов или персональных данных.
