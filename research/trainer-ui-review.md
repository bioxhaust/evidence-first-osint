# Проверка состояния и интерфейса тренажёра

Проверено 3 ноября 2026 года; повторный прогон после исправления повторных попыток — 03:50 UTC. **25 из 25 постоянных Node-тестов и 8 из 8 дополнительных DOM-сценариев прошли**, без пропусков. Машиночитаемый результат: [qa-trainer-ui.json](evidence/qa-trainer-ui.json).

Среда: macOS 26.0.1 (25A362), arm64, Node.js 26.7.0. Дополнительные сценарии выполнены в JSDOM 30.1.3. Новые зависимости в проект не добавлялись.

## Что исправлено и проверено

- Python отмечен дополнительным: основной маршрут продолжается к AI и отчёту без начисления XP за пропуск.
- Сохранение объединяет текущий результат с последним снимком того же профиля; событие `storage` восстанавливает результаты конкурирующих вкладок без цикла перезаписи.
- Выход, включая недоступный сервер завершения сессии, возвращает гостевой прогресс. Потеря авторизации не смешивает личные результаты с гостевыми.
- Восстановленная из локального кэша сессия до проверки показана как неподтверждённая; ошибка OAuth видна пользователю.
- Начало синхронизации сразу отображается. Полученные результаты обновляют XP и доступность уроков.
- Черновики вариантов и числового ответа переживают перерисовку; числовое поле сохраняет фокус и выделение. Черновики остаются в памяти и очищаются при смене профиля.
- Операции, начатые в прежнем профиле, не меняют новый профиль. Проверены границы состояния и поздний результат синхронизации; защита также применяется к импорту и завершению выхода.

## Дополнительные DOM-сценарии

Временный стенд исполнил код `app.js` в JSDOM с настоящими модулями прогресса, учебными заданиями и управляемой имитацией облачного адаптера:

1. Отложенная проверка аккаунта и получение прогресса сохраняют выбранный флажок, обновляют XP и открывают следующий модуль.
2. Числовой черновик, фокус и выделение сохраняются при обновлении из облака.
3. Недоступная сеть оставляет локальную копию аккаунта с явной отметкой; неудачное завершение серверной сессии немедленно возвращает гостевой профиль.
4. Отмена OAuth выводит заметное сообщение на странице профиля.
5. Поздний результат синхронизации аккаунта A не меняет гостевой профиль или аккаунт B после выхода.
6. Основная кнопка продолжения и действие пропуска обходят Python без фиктивного завершения.
7. Событие другой вкладки обновляет прогресс, сохраняя выбранный ответ.
8. После ошибочного, затем правильного ответа и завершения блока новая попытка повторения начинается пустой. Повторное открытие завершённого блока также очищает прежние ответы, в том числе у последующих заданий. Возврат к незавершённому блоку и обновление внутри текущей попытки сохраняют её черновик; XP не начисляются повторно. Дополнительно проверена подпись «Профиль» в заголовке при неподключённом облаке.

Восьмой сценарий до исправления воспроизвёл регрессию: в новом повторении первого задания оставались выбранными правильные варианты `1` и `2`. Исправление очищает черновики только при явном начале новой попытки завершённого задания или очереди повторения. Проверка очистки также добавлена в существующий Node-тест без изменения общего числа тестов. Подпись кнопки очереди заменена на «Заданий для повторения: 1», чтобы не зависеть от склонения числительного.

## Ограничения

JSDOM проверяет DOM, обработчики событий и состояние, но не внешний вид в настоящем браузере, мобильную вёрстку или работу вспомогательных технологий. Облако в этих сценариях имитировалось: результат не подтверждает действующий GitHub OAuth, настройку провайдера, доступность Supabase, RLS или реальную синхронизацию между устройствами. Для них нужна отдельная проверка опубликованного сайта.

Временный DOM-стенд не включён в репозиторий и не запускается через `npm test`; сохранён отчёт о фактически выполненных восьми сценариях. Следующее улучшение — добавить постоянные браузерные регрессионные проверки с явно выбранной тестовой зависимостью. Постоянная Node-серия остаётся из 25 тестов.
