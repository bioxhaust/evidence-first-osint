# Первичные источники и границы утверждений

Дата исследования: **2026-11-03**. Это редакторская проверка источников для Evidence First OSINT. Машиночитаемый журнал запросов находится в [source-checks.json](source-checks.json). Ссылки ведут к издателям стандартов, регуляторам, разработчикам или самим сервисам; OpenStreetMap Wiki отдельно отмечена как документация сообщества.

Проверка означала HTTP GET и чтение относящихся к теме разделов. Она **не** означает испытание всех функций сервиса, юридическое заключение, подтверждение его доступности во всех странах или запуск API с учётными данными. HTTP 200 с переадресацией на главную страницу не принят за подтверждение искомой публикации. Тексты источников не включены в учебные наборы; ниже — собственные краткие выводы и ссылки.

## 1. Метод исследования: Berkeley Protocol

- [Berkeley Human Rights Center: Developing the Berkeley Protocol](https://humanrights.berkeley.edu/projects/developing-the-berkeley-protocol-on-digital-open-source-investigations/) — HTTP 200, страница проекта прочитана. Описывает стандарты выявления, сбора, сохранения, проверки и анализа открытой цифровой информации, а также правовые и этические аспекты.
- [OHCHR: Berkeley Protocol](https://www.ohchr.org/en/publications/policy-and-methodological-publications/berkeley-protocol-digital-open-source) — в этой среде HTTP 403; содержание этой страницы повторно не подтверждено.

Применение: разделять наблюдение, вывод и гипотезу; фиксировать происхождение файла и действия аналитика; сохранять сведения, которые противоречат предпочитаемой гипотезе. Протокол не превращает любой скриншот в допустимое судебное доказательство. Вопрос допустимости зависит от процесса и юрисдикции. Обязательная практика использует собственные синтетические материалы и не воспроизводит работу с травмирующим контентом.

## 2. Приватность: конкретный пример права ЕС

- [Regulation (EU) 2016/679, GDPR, EUR-Lex](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng) — официальный идентификатор акта. Три варианта HTML/PDF дали HTTP 202 с пустым телом; актуальная редакция текста в этом запуске не прочитана.
- [EDPB: Respect individuals’ rights](https://www.edpb.europa.eu/sme/be-compliant/respect-individuals-rights_en) — HTTP 200, прочитано официальное руководство регулятора.

Редакторская привязка для курса: статья 3 GDPR относится к территориальной сфере, статья 5 — к принципам обработки, включая минимизацию, статья 6 — к правовым основаниям, статья 9 — к особым категориям данных, статья 85 — к согласованию защиты данных со свободой выражения и информации через право государств. Это ориентиры для чтения акта, а не утверждение, что GDPR применяется к любому человеку в любой стране. Для реального проекта следует проверить применимое право, актуальную редакцию и национальные журналистские исключения. Публикация сведений в интернете сама по себе не отменяет права человека и обязанности оператора.

Практическое правило курса: заранее определять цель, собирать только необходимые поля, исключать домашние адреса и контакты людей из публичного отчёта, задавать срок хранения и не загружать персональные данные в внешние ИИ-сервисы. В учебном кейсе используются вымышленные организации и адресные коды.

## 3. Robots.txt и разрешение доступа

[RFC 9309, Robots Exclusion Protocol](https://www.rfc-editor.org/rfc/rfc9309.html) — HTTP 200, прочитан. Раздел 1 прямо отделяет правила robots.txt от авторизации доступа.

Следствие: разрешение обхода в robots.txt не выдаёт лицензию на перепубликацию, не отменяет условия платформы и не создаёт правового основания обработки персональных данных. Отсутствие файла также не даёт такого разрешения. Ограничения доступа, CAPTCHA и лимиты не предлагается обходить. Для практики достаточно скачанного учебного набора; живые API — дополнительный маршрут после проверки правил конкретного сервиса.

## 4. Поиск: документированные операторы

- [Google Search Help: Refine Google searches](https://support.google.com/websearch/answer/2466433?hl=en) — HTTP 200. Документированы кавычки, `site:`, исключение через `-`, `before:`, `after:`, `filetype:`. Между оператором и значением не ставится пробел.
- [Microsoft: Advanced search options](https://support.microsoft.com/en-us/bing/advanced-search-options) — HTTP 200. Документированы кавычки, группировка, `AND`, `OR`, `NOT`; `OR` и `NOT` должны быть прописными. Страница предупреждает о региональных различиях функций.
- [Microsoft: Advanced search keywords](https://support.microsoft.com/en-us/bing/advanced-search-keywords) — HTTP 200. Документированы `site:`, `filetype:`, `language:`, `intitle:` и другие ключевые слова.

Поисковая выдача не является реестром всех существующих документов. `site:` не доказывает полноту индексации. Дата в поисковом фильтре не доказывает время события или съёмки. Операторы разных систем не следует объявлять взаимозаменяемыми. В обязательных заданиях ученик проектирует запросы и применяет критерии к локальному корпусу; корпус не имитирует ранжирование Google/Bing. Коммерческий или закрывшийся поиск не должен быть условием прохождения курса. Не включаем старые операторы только потому, что они встречались в старых шпаргалках.

## 5. Метаданные и проверка медиа

[ExifTool FAQ](https://exiftool.org/faq.html) — HTTP 200, прочитаны разделы о чтении/записи тегов и датах. Программа поддерживает изменение метаданных; наличие тега не гарантирует его истинность. Часовой пояс может отсутствовать, платформы могут удалять теги, а время изменения файла не равно времени съёмки.

Безопасный пример чтения: `exiftool -G1 -a -s sample.jpg`. Это пример по документации: факт запуска конкретной версии программы на материалах курса должен отдельно попадать в отчёт о проверке. Работать нужно с копией, сохраняя исходные байты. Отсутствие GPS или EXIF не свидетельствует о подделке. Обратный поиск даёт кандидатов на сравнение; ранняя найденная публикация ограничивает время существования изображения, но не устанавливает автора или момент съёмки. Для автономной практики достаточно собственных исходного и обрезанного изображений с явной маркировкой синтетического происхождения.

## 6. Карты и спутниковые снимки

- [OpenStreetMap Copyright and License](https://www.openstreetmap.org/copyright) — HTTP 200. Данные OSM распространяются по ODbL; необходима атрибуция, а условия для производных баз нужно проверять отдельно. Не переносить лицензию базы автоматически на чужие тайлы и спутниковые снимки.
- [OpenStreetMap Wiki: Accuracy](https://wiki.openstreetmap.org/wiki/Accuracy) — HTTP 200. Документация сообщества о позиционных ошибках, GPS и геопривязке. Это не гарантия точности для любого участка карты.
- [OpenStreetMap Wiki: Vertical Aerial Photographs](https://wiki.openstreetmap.org/wiki/Aerial_imagery) — HTTP 200. Условия использования источников снимков требуют отдельной проверки; возможность посмотреть изображение не равна праву распространять его.
- [Copernicus SentiWiki: S2 Mission](https://sentiwiki.copernicus.eu/web/s2-mission) — HTTP 200. Sentinel-2 имеет 13 спектральных полос: четыре с пространственным разрешением 10 м, шесть — 20 м, три — 60 м.

Разрешение пикселя, позиционная точность, дата наблюдения и облачность — разные ограничения. Увеличение масштаба отображения не создаёт деталей. По Sentinel-2 нельзя обещать чтение автомобильных номеров. Учебная карта курса оригинальная, в условной сетке метров, без выдачи её за координаты WGS84. Число знаков после запятой не является мерой уверенности.

## 7. Компании: пример Великобритании

- [Companies House: Search the register](https://find-and-update.company-information.service.gov.uk/) — HTTP 200, поисковая форма доступна; на странице есть предупреждение о точности поданных сведений. Индивидуальные компании в ходе этой проверки не исследовались.
- [Developer Hub](https://developer.company-information.service.gov.uk/) — HTTP 200.
- [Authorisation](https://developer-specs.company-information.service.gov.uk/guides/authorisation) — HTTP 200. Для API нужен ключ; он передаётся как имя пользователя HTTP Basic, пароль может быть пустым.
- [Rate limiting](https://developer-specs.company-information.service.gov.uk/guides/rateLimiting) — HTTP 200. Документация указывает до 600 запросов за пять минут; при превышении возвращается HTTP 429. Это ограничение, а не рекомендуемая скорость.

Название компании недостаточно для объединения записей. Нужны номер, юрисдикция и дата. Общий адрес может означать коворкинг или регистрационного агента; он не доказывает общего владельца. Сумма договора не равна сумме выплат, а плановая операция не равна исполненной. Данные другого реестра могут иметь иные определения полей. Ключи и работа API в этой проверке не использовались; основной маршрут — оригинальные CSV, дополнительный — ручной публичный интерфейс или API после регистрации и проверки правил.

## 8. Домены, RDAP, DNS и сертификаты

- [ICANN: Registration Data Access Protocol](https://www.icann.org/en/contracted-parties/registry-operators/resources/registration-data-access-protocol) — HTTP 200. RDAP — стандартизированный протокол доступа к регистрационным данным; не следует преподавать WHOIS как единственный современный интерфейс.
- [RFC 9162: Certificate Transparency Version 2.0](https://www.rfc-editor.org/rfc/rfc9162.html) — HTTP 200. Стандарт описывает публикацию и аудит сведений о TLS-сертификатах; это не обещание, что каждый интерфейс CT реализует именно версию 2.
- [crt.sh, пример для example.com](https://crt.sh/?q=example.com) — HTTP 200, получена таблица сертификатов. Проверен один неаутентифицированный поисковый запрос; массовая доступность, полнота и SLA не подтверждены.

Сертификат показывает запись об именах и периоде действия, а не личность владельца сайта или дату начала его работы. Общий IP может принадлежать CDN/хостингу. Исторический IP нельзя подменять текущим. Пассивность относительно исследуемой системы не означает анонимность: запрос виден поставщику данных и иногда резолверу. В учебном наборе используются только `.example` и адреса TEST-NET; их не нужно разрешать через сеть. Архив JSON обеспечивает повторяемость при недоступности внешних интерфейсов.

## 9. Публичные социальные платформы

- [YouTube Data API Overview](https://developers.google.com/youtube/data/getting-started) — HTTP 200, прочитана документация. На дату проверки описаны отдельные суточные квоты: 100 вызовов `search.list`, 100 `videos.insert` и 10 000 единиц для прочих endpoints вместе. Квоты могут изменяться; нельзя копировать старую универсальную формулу без даты и проверки.
- [Reddit Data API Terms](https://redditinc.com/policies/data-api-terms) — HTTP 200. Доступ условный и отзывный; коммерческие и некоторые иные сценарии требуют отдельного соглашения. Страница справки Reddit API Access вернула 403 и не использовалась как доказательство нынешней доступности.

Публичный пост, разрешение API, право хранения и право распространения — четыре разных вопроса. Число репостов не равно числу независимых свидетельств. Удалённый пост или отсутствие результата поиска не доказывают отсутствие события. Не делаем массовый сбор людей обязательной практикой; анализируем синтетический корпус постов и его явные ссылки на источник.

## 10. Python и разрешённые API

- [Python csv](https://docs.python.org/3/library/csv.html) — HTTP 200. Для файлов CSV важны явная кодировка, `newline=''`, разделитель и схема полей.
- [Python urllib.request](https://docs.python.org/3/library/urllib.request.html) — HTTP 200. Документированы `urlopen` и тайм-ауты. Чтение документации не подтверждает работу конкретного учебного скрипта.

Дополнительно прочитаны официальные справочники [re](https://docs.python.org/3/library/re.html), [decimal](https://docs.python.org/3/library/decimal.html) и [json](https://docs.python.org/3/library/json.html). Для необязательного сетевого примера используются [GitHub REST Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository) и [правила лимитов](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).

Обязательная воспроизводимость обеспечивается локальными JSON/CSV. Для денег предпочтительны целые единицы или `Decimal`, а не двоичный `float`. Недопустимо заменять неизвестную сумму нулём, терять дубликаты без журнала или молча считать плановые платежи исполненными. Дополнительный сетевой код должен явно ограничивать время ожидания, объём и число запросов, обрабатывать 429 и не сохранять ключи в репозиторий.

Отдельная проверка запуском: оба Python-блока урока 16 выполнены на Python 3.15.2, macOS. Локальный пример получил PAY-01/PAY-02 и сумму 5000000; необязательный одиночный неаутентифицированный GET к `https://api.github.com/repos/python/cpython` вернул `python/cpython`. Запрос ограничен тайм-аутом и объёмом ответа, не изменяет серверные данные. Это подтверждает один конкретный пример, а не поддержку всех ОС или работоспособность иных API. Авторизованные API с ключами не испытывались.

## 11. ИИ и происхождение контента

- [C2PA and Content Credentials Explainer 2.2](https://spec.c2pa.org/specifications/specifications/2.2/explainer/Explainer.html) — HTTP 200. Прямо отделяет проверку происхождения и целостности от истинности изображённого содержания.
- [C2PA FAQ](https://c2pa.org/faqs/) — HTTP 200. Описывает возможность удаления метаданных и механизмы восстановления связи.
- [C2PA Technical Specification 2.2](https://spec.c2pa.org/specifications/specifications/2.2/specs/C2PA_Specification.html) — HTTP 200; выборочно прочитаны относящиеся к происхождению разделы, весь большой стандарт построчно не аудировался.

Наличие Content Credentials не доказывает правдивость сцены; отсутствие не доказывает генерацию ИИ. Вывод детектора без независимой проверки не становится доказательством. ИИ годится для предложений гипотез, черновой классификации и объяснения кода, но каждый факт и ссылка проверяются человеком. Нельзя разрешать модели незаметно дописывать отсутствующую дату, владельца домена или мотив участников.

## 12. Лицензирование собственных и сторонних материалов

- [CC BY 4.0 — legal code](https://creativecommons.org/licenses/by/4.0/legalcode.en) — HTTP 200. Выбрана для собственного учебного текста и оригинальных синтетических материалов: нужны атрибуция, ссылка на лицензию и обозначение изменений при адаптации.
- [MIT License, OSI](https://opensource.org/license/mit) — HTTP 200. Выбрана для собственного кода: сохраняются уведомления об авторском праве и лицензии.

Лицензии распространяются только на то, чем автор вправе распоряжаться. Внешние статьи, логотипы, скриншоты платформ, картографические тайлы и фотографии не становятся CC BY 4.0 от ссылки на них. Самый воспроизводимый основной маршрут — собственные иллюстрации и записи с явной маркировкой `SYNTHETIC / УЧЕБНЫЙ МАТЕРИАЛ`. Зависимости сайта сохраняют собственные лицензии. Рекомендуется отдельный реестр происхождения активов; для внешних источников курса достаточно ссылок.
