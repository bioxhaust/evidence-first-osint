# Security and privacy reports

Do not post credentials, private personal data or a working attack against a real target in a public issue. Use GitHub **Security → Report a vulnerability** if the private reporting option is enabled. Otherwise use GitHub's abuse reporting for exposed personal data; a public issue may say only that a private reporting route is needed, without the sensitive content.

For ordinary broken examples, use the content issue template with synthetic reproduction data. This is a static educational project, not a monitoring service. There is no guaranteed response time or bug bounty.

All practice uses fictional subjects and local files. Python examples do not justify collecting data contrary to access restrictions, applicable law or service terms.
